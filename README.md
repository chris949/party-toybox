# ティアリストウォーズ

**あの人の「順位」、当てられる？**

みんなが作ったお題を誰かが自分の好みで並べ、ほかの全員がその順位を予想して当てる、オンラインのパーティーゲームです。通話をつなぎながら、各自のスマホやPCのブラウザで遊びます。

▶ **あそぶ：https://chris949.github.io/tier-list-wars/**

インストールもアカウント登録も要りません。サーバーを持たない P2P 方式なので、運営費もかかりません。

---

## あそびかた

### 準備（各自、遊ぶ前に）

1. 上のURLを開いて名前を入れる
2. 「お題の設定」でお題を作る
   - お題1つにつき選択肢は5〜50個。「出題数」（5〜10個）を決めておくと、ゲームではその数だけランダムに出ます。多めに作っておくと、毎回違う組み合わせで遊べます
   - 例）「好きな野菜は？」→ じゃがいも／にんじん／たまねぎ／キャベツ／トマト
   - チェックを入れたお題が、次のゲームに持っていくお題になります
   - 最初からサンプルのお題が10個入っているので、作らなくても遊べます。ただし自作のお題が優先して配られるので、作った方が盛り上がります

### ゲームの流れ（4〜10人）

1. **部屋を作る**：ホスト役が「部屋を作る」を押し、表示された6文字の部屋コード（または招待リンク）をみんなに送る
2. **集まる**：ほかの人は部屋コードを入れて「参加」。そろったらホストが「ゲーム開始」
   - ホストはロビーで「出題方式」を選べます。**全部からランダム**（初期値）か、**作成者ごとに1つずつ**（自作のお題を持ってきた人のお題は必ず1つ出る）
3. **準備フェーズ**：みんなのお題が1人1つずつ配られるので、**自分の好み**で1位から順に並べる（タップでも、ドラッグでも並べられます）
4. **予想フェーズ**：「〇〇さんの『お題』の順位は？」を、本人以外の全員が予想する
   - 並べる時間はどちらも**60秒**。並べ終えていれば、決定を押し忘れても提出されます。並べ終えていないとき、準備フェーズは残りがランダムで埋まり、予想フェーズは未提出（0点）になります
   - 問題数は参加人数と同じです。配られたお題は全部出題されます
5. **答え合わせ**：正解が最下位から1位へ自動でめくられる。めくるたびに、全員の予想が当たったか外れたか分かる
6. 全員分のラウンドが終わったら最終結果。得点がいちばん高い人の勝ち

### 得点

| | 点 |
|---|---|
| 順位が1つ一致するごと | +1 |
| 全部一致（パーフェクト） | さらに +3 |

## 遊ぶ前に知っておいてほしいこと（P2Pならではの注意）

このゲームはサーバーを使わず、**ホスト（部屋を作った人）のブラウザが進行役**になって、参加者の端末同士が直接つながります。そのため、次の点に気をつけてください。

### ホストについて

- **ホストが退出・切断すると、部屋は解散します。** 回線が安定していて、途中で抜けない人がホストをしてください。PCがおすすめです
- **ホストはスマホの画面を消さないでください。** 画面が消えたりアプリを切り替えたりすると、ブラウザが通信を止めて部屋が落ちることがあります
- ホストのブラウザにはゲームの全情報（全員の回答）が集まります。友人同士で遊ぶ前提なので、ホストのズルは防いでいません

### 参加者について

- 通信が切れると「再接続中…」と出て、自動でつなぎ直します。15秒たってもつながらないときはホームに戻るので、**同じタブのまま**「参加」を押してください。部屋コードは入力済みになっていて、ゲーム中でも元の状態に戻れます（タブを閉じると別人扱いになり、ゲーム中は入れません）
- 切断に気づかれず、みんなが待ち続けてしまうことがあります。そのときはホストが「未提出の人を待たずに進める」を押してください
- ゲームが始まった後からは、新しい人は参加できません

### 音について

- BGM と効果音が鳴ります。右上の 🔊 を押すと「BGM＋効果音 → 効果音だけ → 音なし」と切り替わります
- スピーカーで鳴らすと、通話のマイクに音が入ることがあります。気になる人はイヤホンを使うか、音を切ってください

### つながらないとき

- まず全員が同じURLを開いているか確認してください
- 会社や学校のネットワーク、一部のモバイル回線やVPNでは、端末同士の接続が制限されていてつながらないことがあります。その場合は自宅のWi-Fiやテザリングに切り替えて試してください
- 接続の仲介には、PeerJS の無料公開サーバーを使っています。このサーバーが止まっているときは遊べません（時間をおいて試してください）

## プライバシーとセキュリティ

- **参加者同士には、互いのIPアドレスが見えます。** P2P（端末同士の直接接続）の仕組み上、避けられません。知らない人とは遊ばないでください
- ゲームの通信は暗号化されています。直接つながらないときは PeerJS の中継サーバーを経由しますが、中身は読まれません
- 名前とお題は、**自分のブラウザの中にだけ**保存されます。どこかのサーバーに送られることはありません。別の端末やブラウザには引き継がれません
- 部屋コードを知らない人は部屋に入れません。もし知らない人が入ってきたら、ホストがロビーで ✕ を押して追い出せます
- 名前やお題はほかの参加者に表示されます。本名や個人情報は入れないことをおすすめします

詳しい対策内容は [docs/spec.md の 7.5](docs/spec.md) にまとめています。

## 開発者向け

React ＋ Vite ＋ TypeScript で作っています。構成と方針は [docs/architecture.md](docs/architecture.md) を見てください。

### 構成

| 場所 | 内容 |
|---|---|
| `src/core/` | どのモードでも共通のルール（部屋・参加・開始など）。画面も通信も使わない |
| `src/modes/tier/` | 今のモードのルール（`rules.ts`）、見せる情報（`view.ts`）、専用の画面（`screens/`） |
| `src/net/` | P2P 通信（PeerJS、見張り、自動再接続） |
| `src/app/` `src/ui/` | 画面と、共通の画面部品 |
| `src/audio/` `src/storage/` | 音、端末への保存 |
| `tests/` | ルールの自動テストと、CPU同士のシミュレーション |
| `docs/` | 仕様書（`spec.md`、仕様の唯一の正）、技術構成、バックログ、テスト記録 |
| `legacy/v0.8.0.html` | 作り直す前の版（参照用。公開はされない） |

### 手元で動かす

```bash
npm install
npm run dev
```

表示された URL（http://localhost:5173/ など）を開きます。URL の末尾に `?dev` を付けると、2人から開始できます（動作確認用）。同じブラウザでもタブごとに別の参加者になるので、タブを複数開けば1人で通しで試せます。`?dev` のときは、開発者ツールから `__tlw.store`（画面の状態）と `__tlw.session`（通信）を触れます。

```bash
npm test
```

ルールの自動テストと、300ゲームのシミュレーションが走ります。

### 進め方

1. 改善したいことは、まず `docs/backlog.md` に書き出す
2. 実装する前に `docs/spec.md` を更新して合意する
3. 1回の変更は1テーマ。実装したらテストプレイで確かめ、結果を `docs/playtest-log.md` に記録する

### 公開

`main` ブランチに push すると、GitHub Actions がテスト → ビルド → GitHub Pages への公開を行います（1〜2分）。テストが通らないと公開されません。

公開するたびに `package.json` の `version` を上げてください。ホーム右上に表示され（マウスを載せるとコミットのIDも出ます）、ホストと違う版の参加者がいるとロビーで警告が出ます。
