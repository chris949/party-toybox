# ダイスレイド

すごろくで準備して、みんなでボスを倒す、協力ゲーム。ほかのゲームより長く、じっくり遊ぶ（10〜20分・2〜4人）。

- 遊ぶ：https://chris949.github.io/party-toybox/ （ホストが、ロビーで「モード」を **ダイスレイド** にする）
- ゲーム集ぜんたいの説明・遊ぶ前の注意：[README](../../../README.md)・[docs/guide.md](../../../docs/guide.md)

## あそびかた

- 席は4つ。人が座らない席は、CPU の仲間が埋める。勝ち負けは、全員で同じ
- ロビーで、自分の職業（戦士・魔法使い・僧侶・弓兵）を選べる。選ばなければ、空いている職業になる
- 自分の番に、サイコロを2つ振る。1つを「移動」、もう1つを「行動」に使う
- マスの効果でコインやカードを集め、レベルを上げ、ザコを倒して強くなる
- 決戦のラウンドになると、ボスが現れる。全員で協力して倒せば勝ち。チームのライフがなくなると負け
- 終わったあとに、貢献度の順位が出る

- 出目が1〜2のときは、集中トークンが貯まる。出目の±1や、振り直しに使える。チームのサイコロと交換して、仲間と出目を融通することもできる
- 赤いマスは、ボスの次の攻撃の範囲。内側の輪ではボスを攻撃できるが、毎ラウンド反撃も受ける
- 盤面は、ドラッグで動かせる。右上のボタンで、演出の速さ・カメラ・音を変えられる

細かい決まり（チップ・カード・ボスの行動の数字）は、まだこの文書に書いていない（`engine/` の中にある）。

## 仕様

- **ここから下が、このモードの仕様の正**。変更は「この文書を更新 → 合意 → 実装」の順で行う
- 部屋・通信・切断・見た目・音など、どのモードにも共通の決まりは [docs/spec.md](../../../docs/spec.md) にある
- 章の番号（例：18.2）は、コードのコメントや、ほかの文書から指すための番号
- **［提案］** と付けたところは、話し合いで決めていない細部を、実装のときに補ったもの
- このフォルダの中身：`engine/`（ゲームの中身。別に作っていたものを持ち込んだ）／`rules.ts`（部屋とのつなぎ役）／`actions.ts`（届いた操作の検査）／`view.ts`（参加者に見せる情報）／`Lobby.tsx`（ロビーの設定）／`screens.tsx`（盤面のページを開く枠）
- 盤面のページは、リポジトリの直下の `raid/`（`index.html` と `src/`）。絵は `public/raid/`
- コマ絵（味方4職とモンスター4種）は、1枚の素材集から `scripts/raid_sprites.py` で切り出す。素材集は、背景が透明で、絵どうしの間が空いているもの（絵のつながりをたどって、1体ぶんを丸ごと取り出す。左から何番目の絵を、どの動きに使うかは、スクリプトの中に書いてある）。切り出したあとの大きさは `raid/src/assets.ts` の `SD_HEIGHT` でそろえる

## 18. モード：ダイスレイド

### 18.1 概要

- すごろく＋協力のボス討伐。ほかのモードより長く（10〜20分）、覚えることも多い「じっくり遊ぶ」枠
- 別のプロジェクトとして作っていたものを、パーティトイボックスの部屋と通信に載せる。載せることで、初めてオンラインで遊べるようになる
- 3つの段階に分けて入れた：①ルールと、部屋へのつなぎ込み → ②盤面の画面 → ③職業を選ぶ・通しテスト・ロビーの一覧に出す

### 18.2 ロビーの設定

| 設定 | 選べるもの | 理由 |
|---|---|---|
| 長さ | **クイック（約10分。初期値）／スタンダード（15〜20分）** | ほかのモードが3〜5分なので、初期値は短いほうにした ［初期値は提案］ |

- 人数は2〜4人。**5人以上では、始められない**（席が4つのため）［提案。見ているだけの参加は、あとで検討］
- CPU の参加者を足せる（共通の仕様 2.1）。足した CPU は、CPU の席として扱う

### 18.3 席と操作

- 席は4つ。開始時に、参加者をランダムな順に座らせ、残りは CPU の席にする
- **職業**（戦士・魔法使い・僧侶・弓兵）：ロビーにいる間、各自が選べる。誰が何を選んだかは、全員に見える。同じ職業を選ぶ人がいてもよい ［提案］。選ばなかった人と CPU の席は、まだ誰も使っていない職業から順に割り当てる
- **自分の席の番のときだけ、操作できる**。誰の操作かは、届いた中身ではなく、送ってきた人の席で決める
- 操作には、通し番号を付ける。番号が合わない操作（二重に届いた、など）は、受け取らない
- CPU の席は、0.7秒の間を置いて、ホストが進める
- **切断した人の席は、CPU が代わりに動かす**（戻ってくれば、また自分で動かせる）

### 18.4 通信と、見せる情報

- **ホストが正**。ゲームの中の乱数は、開始時に決めた種から作るので、ホストだけが進めても結果がぶれない
- 協力ゲームで隠す情報がないので、**全員に同じ盤面を送る**（自分の席の番号だけが、人によって違う）
- 直前の操作で起きたこと（演出用）と、操作の通し番号も送る

### 18.5 画面

- 盤面の画面（Phaser で作ってあるもの）を、**別のページ（`raid/index.html`）として置き、部屋の画面が枠（iframe）の中に開く**
  - 理由：盤面の見た目の決まりが、ページ全体に掛かる書き方（`button`・`.card`・`body` など）で、同じページに混ぜると、ほかの画面の見た目とぶつかるため
  - Phaser（約1.2MB）と絵（約5.7MB）は、このモードを開いた人だけが読み込む。片付けは、枠を消すだけで済む
- 部屋の画面（親）と、盤面のページのやり取り（同じ場所から開いたページどうしの連絡だけを受け取る）
  - 親 → 盤面：自分の席とホストかどうか（最初に1回）／いまの盤面・直前に起きたこと・通し番号（操作が1つ進むたび）
  - 盤面 → 親：用意ができた／自分の番の操作／（結果の画面で、ホストが）ロビーに戻る
- **盤面のページは、ゲームを進めない**。届いた盤面を順に演出するだけ。演出より速く届いてたまってきたら、演出を飛ばして追いつく。途中が抜けたとき（つなぎ直したあと）は、演出なしで、いまの盤面にする
- 操作できるのは、自分の席だけ。見ているだけの人は、どの席も操作できない
- 画面の上の細い帯に、タイトルと「退出」が残る。盤面のページが自分の音を鳴らすので、その間、部屋の側の BGM と効果音は止める
- 結果の画面の「もう一度遊ぶ」は、ホストには「ロビーに戻る」、ほかの人には「ホストがロビーに戻すのを待っています」として出す

### 18.6 終わり方

- ボスを倒せば勝ち、チームのライフがなくなるか、ラウンドが尽きれば負け。勝ち負けは全員で同じ
- 貢献度を点として、順位を出す
