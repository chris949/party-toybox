# ティアリストウォーズ 技術構成

- 状態: **合意済み・移行済み（v0.9.0）** 2026-11-04
- 対象: v0.8.0（`index.html` 1枚）から、React ＋ Vite ＋ TypeScript への移行と、その後の開発
- ゲームの仕様は [spec.md](spec.md) が正。この文書は「どう作るか」を決める

---

## 1. 方針

| # | 方針 | 理由 |
|---|---|---|
| 1 | **ゲームのルールを、通信と画面から切り離す** | ルールだけを自動テストでき、CPU同士のシミュレーションで偏りも確かめられる。直したときに別の所が壊れにくくなる |
| 2 | **ゲームモードを差し替えられる部品にする** | 今後、別のモードを足すため。部屋・参加者・通信・タイマーなどの共通部分は、どのモードでも使い回す |
| 3 | **ホストが正（今と同じ）** | ゲームの状態はホストだけが持つ。参加者には「その人に見せてよい情報」だけを送る |
| 4 | **移行中は機能を変えない** | 見た目も動きも v0.8.0 と同じものを作り直す。移行と機能追加を混ぜると、何が原因で壊れたか分からなくなる |
| 5 | **演出は段階的に足す** | ふつうのアニメーションは画面部品の中で作る。粒子や、リアルタイムに動くミニゲームが必要になったら、その部分だけ描画ライブラリを組み込む |

## 2. 使う技術

| 用途 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | TypeScript | ホストと参加者がやり取りするメッセージの形を型で決め、食い違いのバグを防ぐ |
| 画面 | React | 文字・リスト・入力欄が中心のゲームに向く。状態が変わった部分だけ描き直すので、今の「まるごと描き直す」ための回避策が要らなくなる。定番の道具が多い |
| ビルド | Vite | 速く、設定が少ない。開発中は保存するとすぐ画面に反映される |
| 通信 | PeerJS（npm で導入） | 今と同じ。CDN から読み込む必要がなくなり、改ざん対策のハッシュ（SRI）も不要になる |
| 画面の状態 | Zustand | 小さく、覚えることが少ない。ホストの状態や受け取った状態を、どの画面からも読めるようにする |
| アニメーション | Motion（旧 Framer Motion。`motion/react`） | めくり・カードの裏返し・画面の切り替え・並び替えの動き |
| ドラッグ＆ドロップ | dnd-kit | スマホの指操作に強い。マウスは少し動かすと、指は少し長押しするとつかめる（すぐ動かした指はスクロールになる） |
| 見た目 | CSS（CSS変数で色や角丸を一か所にまとめる） | v0.5 のデザイン（水色ポップ）をそのまま移す |
| 音 | Howler.js（v0.10 から）。曲や効果音のファイルがないものは Web Audio の合成音で鳴らす | 調査メモの use-sound は Howler.js を React 用に包んだもの。このゲームの音は画面部品ではなく状態の変化から鳴らすので、Howler.js を直接使う方が素直。スマホで音が出ない問題への対処や、曲のループ・音量の徐々の変化も Howler.js がやってくれる |
| 各自の曲の保存 | IndexedDB（ブラウザの中のデータベース） | 曲ファイルは大きく、localStorage（数MBまで）には入らない |
| 紙吹雪 | canvas-confetti（v0.10 から） | 軽く、数行で使える |
| 文字 | M PLUS Rounded 1c（`@fontsource/m-plus-rounded-1c`、v0.10 から） | 使う文字の分だけ読み込む仕組みなので、日本語でも重くなりにくい |
| テスト | Vitest | ルールの自動テストと、CPU同士のシミュレーション |
| 公開 | GitHub Actions → GitHub Pages | push するとテスト・ビルドをして自動で公開する |

ライブラリのバージョンは、導入する時点の安定版に固定する（`package-lock.json` を残す）。

**将来、必要になったら足すもの**（`~/work/quiz-game-ui-libraries.md` の調査結果も参考にする）

| やりたいこと | 足すもの |
|---|---|
| 紙吹雪・キラキラなどの粒子 | canvas-confetti（または react-confetti-explosion）。もっと凝るなら PixiJS（画面の一部に重ねて描く） |
| 既製の演出アニメ（○×、星、トロフィーなど） | lottie-react |
| 状態に反応するキャラクターやボタン | Rive（`@rive-app/react-canvas`） |
| 円形の制限時間表示 | react-countdown-circle-timer |
| Windows・Android でも丸ゴシックにする | M PLUS Rounded 1c をサイトに同梱する（`@fontsource/m-plus-rounded-1c`。外部のフォント配信を使わない） |
| 見た目の部品化を進める | Tailwind CSS ＋ shadcn/ui。今の CSS 変数のデザインを移す形で検討する |
| 進行がもっと複雑なモード | XState（状態機械）。今は `reduce` で足りている |
| 効果音を録音・既製の音源にする | use-sound。今はブラウザの中で合成しているので不要 |
| キャラクターが動く・当たり判定があるリアルタイムのミニゲーム | Phaser または PixiJS を、そのモードの画面の中だけに埋め込む |
| 複数タブでの自動の通しテスト | Playwright |

## 3. ディレクトリ構成

```
tier-list-wars/
  index.html              入口（中身はほぼ空。src/main.tsx を読み込む）
  package.json
  vite.config.ts
  src/
    main.tsx              起動
    app/                  画面の切り替え（ホーム／お題／ルーム）、全体のレイアウト
    core/                 どのモードでも共通のルール（画面も通信も知らない）
      room.ts             部屋・参加者・参加と退出・ロビーの設定
      engine.ts           ホストの進行：操作を受けて状態を進める、タイマーの管理
      types.ts            状態・操作・メッセージの型
      random.ts           乱数（テストで結果を固定できるよう、外から差し込む）
    modes/
      tier/               今のモード「ティアリストウォーズ」
        rules.ts          配り方・出題数・並び替えの受け付け・時間切れ・得点
        view.ts           各参加者に見せてよい情報を作る（正解を隠す）
        screens/          このモード専用の画面（準備・予想・答え合わせ）
      index.ts            モードの一覧（ロビーで選べるようにする）
    net/                  P2P 通信
      peer.ts             PeerJS の接続、部屋コード
      host.ts             ホスト側：受け取り、送信、見張り
      guest.ts            参加者側：参加、自動再接続、送信の確認
      protocol.ts         やり取りするメッセージの形と、受け取った値の検査
    ui/                   共通の画面部品（ボタン、カード、ロビー、結果、確認ダイアログ）
    audio/                BGM・効果音
    storage/              お題・名前・設定の保存（形式が変わったときの移し替えも含む）
    styles/               デザインの色・角丸・影など（CSS変数）
  tests/
    tier.rules.test.ts    配り方・得点・時間切れなどのテスト
    simulation.test.ts    CPU同士で何百回も遊ばせて、偏りや止まる所がないかを見る
  docs/                   仕様書・バックログ・テスト記録・この文書
  .github/workflows/
    deploy.yml            テスト → ビルド → GitHub Pages に公開
```

### 依存の向き

```
app / ui / modes/*/screens   （画面）
        │ 読む
        ▼
      store（Zustand）  ◀── net（通信）
        │                    │
        ▼                    ▼
   core / modes/*/rules・view  （ルール：ほかの何にも依存しない）
```

- **ルール（`core/`・`modes/*/rules.ts`・`view.ts`）は、画面・通信・ブラウザの機能を一切使わない。** 時刻と乱数も引数で受け取る。これでテストが書ける
- 画面は、ルールを直接書き換えない。「操作」を送るだけにする（ホストなら自分のエンジンへ、参加者なら通信でホストへ）

## 4. ゲーム進行の仕組み

### 4.1 ホストのエンジン

ホストは「今の状態」と「操作」から「次の状態」を作る。

```ts
// 状態を進める（同じ入力なら必ず同じ結果になる）
reduce(state, action, { now, random }) => nextState

// 各参加者に送る情報（正解などを隠す）
view(state, playerId) => PlayerView

// 次に時間で起きること（制限時間、めくりの間隔）
nextTimer(state) => { at: number, action } | null
```

- 参加者から届いた操作も、ホスト自身の操作も、タイマーも、すべて `reduce` を通す
- 状態が変わったら、全員に `view` を送る（今の `broadcast` と同じ）

### 4.2 ゲームモードの形

```ts
interface GameMode {
  id: string                 // 'tier'
  name: string               // 'ティアリストウォーズ'
  minPlayers: number
  maxPlayers: number
  settings: SettingDef[]     // ロビーで選べる設定（例：出題方式）
  start(room, settings, random): ModeState
  reduce(state, action, ctx): ModeState
  view(state, playerId): ModeView
  nextTimer(state): Timer | null
}
```

画面側は、モードの `id` ごとに専用の画面を登録する（`modes/tier/screens/`）。ロビーで「モードを選ぶ」ボタンを足せば、モードを切り替えて遊べる。

## 5. 通信

v0.8.0 の仕組み（ホストに全員がつながる形、3秒ごとの見張り、自動再接続、送信の確認、なりすまし防止の鍵）を、そのまま `net/` に移す。

| 変更点 | 内容 |
|---|---|
| メッセージの型 | `protocol.ts` に、送受信するメッセージをすべて型として書く。受け取ったら、まず形と値を検査してから使う |
| 通信の版 | 参加するときに「通信の版」を送る。ホストと版が違う人は、ロビーで警告する（今の `APP_VERSION` の仕組みを引き継ぐ） |
| ゲームの中身 | 通信は「操作」と「状態」を運ぶだけにする。モードを足しても `net/` は変えない |

**制約**：ターン制には十分だが、毎秒何十回もやり取りするリアルタイムのモードでは、ホストの回線や端末の性能が効いてくる。そういうモードを足すときに、あらためて検討する。

## 6. 保存データ

| データ | 保存先 | 移行時の扱い |
|---|---|---|
| お題、名前、音の設定 | localStorage | 今の形式（`tlw-topics` など）をそのまま読めるようにする。今後形式を変えるときは、版番号を付けて移し替える処理を書く |
| 参加者ID・鍵・最後の部屋コード | sessionStorage | 今と同じ |

**移行しても、今までに作ったお題は消えない**ようにする（公開URLが同じなので、同じ保存領域を読める）。

## 7. テスト

| 種類 | 何を確かめるか |
|---|---|
| ルールの自動テスト | 配り方（自作優先、作成者ごとに1つずつ、自分のお題を避ける、重複まとめ）、出題数、並び替えの受け付け、時間切れ（準備はランダムで埋める、予想は0点）、得点、問題数＝参加人数 |
| シミュレーション | CPU の参加者で、人数・お題・時間切れ・切断の組み合わせを何百回も回し、途中で止まらないか、得点や配り方に偏りがないかを見る |
| 手動の通しテスト | 今と同じく、複数タブで参加から結果まで遊ぶ（スマホ幅も） |

GitHub Actions では、テストが通らないと公開しない。

## 8. ビルドと公開

- `main` に push すると、GitHub Actions が「テスト → ビルド → GitHub Pages に公開」を行う
- GitHub の Pages 設定の「Source」を「Deploy from a branch」から「GitHub Actions」に変える（移行の最後に一度だけ）
- 公開URLは今と同じ（https://chris949.github.io/tier-list-wars/）
- バージョンは `package.json` の `version` を正とし、ビルド時に画面へ埋め込む。あわせてコミットの短いID（例：`v0.9.0 (a1b2c3d)`）も出し、キャッシュのずれを見分けやすくする
- 手元での確認は `npm run dev`

## 9. 移行の手順

`migrate/react` ブランチで進める。**移行が終わるまで、公開版は v0.8.0 のまま遊べる。**

| 段階 | やること | 終わったことの確かめ方 |
|---|---|---|
| 1 | Vite ＋ React ＋ TypeScript のひな形、GitHub Actions（テストとビルドだけ。公開はまだしない） | ビルドとテストが通る |
| 2 | ルールを `core/` と `modes/tier/` に移し、自動テストとシミュレーションを書く | v0.8.0 の仕様どおりのテストが通る |
| 3 | 通信を `net/` に移す | 2タブでつながり、見張りと再接続が動く |
| 4 | 画面を React に移す（デザインはそのまま。ドラッグは dnd-kit に置き換え） | スマホ幅・複数タブで、参加から結果まで v0.8.0 と同じに動く |
| 5 | 音・保存データの引き継ぎ | 今までのお題が残っている。音が鳴る |
| 6 | 公開の切り替え（Pages の Source を GitHub Actions に） | 公開URLで新しい版（v0.9.0）が動く。古い版の人がいるとロビーで警告が出る |

移行が終わったら、演出（カードの裏返し、紙吹雪など）や新しいモードを、仕様書を更新してから1テーマずつ足していく。
