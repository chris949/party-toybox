## 1. コンセプト

一言で：**あの人の「順位」、当てられる？**

参加者が作ったお題（例：好きな野菜は？）を誰かが自分の好みで並び替え、ほかの全員がその順位を予想して当てるオンラインパーティーゲーム。

### 1.1 想定する遊び方

- 仲の良い友人同士が、通話（Discord・Zoom など）をつなぎながら、各自の端末で遊ぶ

### 1.2 柱（守りたい面白さ）（決定：2026-11-03）

| # | 柱 | 盛り上がる瞬間のセリフ | 迷ったときの判断基準 |
|---|---|---|---|
| 1 | 予想が外れる意外さ | 「え、そっち！？」「絶対1位だと思ったのに！」 | 外れた瞬間が全員に見えて、ツッコめる方を選ぶ |
| 2 | 読み切った達成感 | 「読めてた！」「さすが、わかってる」 | 当てた人が誇れる・褒められる方を選ぶ |
| 3 | お題そのものが面白い | 「誰だよこのお題作ったの（笑）」 | お題を作る・見せることが楽しくなる方を選ぶ |

柱1と2はどちらも「手がかりはあるのに、読み切れるかどうか分からない」状態から生まれる。その状態を作るのはお題の質なので、柱3は1と2の土台にあたる。

### 1.3 やらないこと（決定：2026-11-03）

- テキストチャットや画面内のリアクション機能は作らない（通話前提のため、ツッコミは声で行う。画面は声を出すきっかけ作りに集中する）
- 勝ち負けを重くしない（得点は達成感を見えるようにするためのもの。大差がついて冷める仕組みや、勝つための駆け引きは入れない）
- サーバーを持たない（費用をかけない）

## 2. プレイ環境

| 項目 | 仕様 | 理由 |
|---|---|---|
| 人数 | 4〜10人（URL末尾に `?dev` を付けると2人から開始可。動作確認用） | 依頼時の要件 |
| 通信 | P2P（WebRTC / PeerJS 1.5.4）。最初の接続の仲介だけ PeerJS の無料公開サーバーを使い、ゲームの通信は端末同士で直接行う | サーバー費用をかけないため |
| 構成 | ホスト（部屋を作った人）のブラウザが進行役。ホストがゲーム状態を持ち、各参加者に「その人に見せてよい情報」だけを送る | P2Pで矛盾なく進行させるため |
| 技術構成 | [architecture.md](architecture.md) にまとめる（v0.9 から React ＋ Vite ＋ TypeScript） | 「どう作るか」は仕様と分けて管理するため |
| 動作環境 | PC・スマホのブラウザ。静的ファイルとして配信（GitHub Pages 等を想定） | 配布を簡単にするため |
| 配布 | GitHub Pages で公開：https://chris949.github.io/tier-list-wars/ （リポジトリ chris949/tier-list-wars の main ブランチ直下を配信。push すると反映）（決定：2026-11-04） | 無料で、Git管理と更新を一本化できるため |

## 3. 画面一覧と遷移

```
ホーム ──「お題の設定」──▶ お題の設定 ──「＋お題を作る」/「編集」──▶ お題の作成・編集
  │                         ◀──「← 戻る」──        ◀──「保存」/「キャンセル」──
  │
  ├─「部屋を作る」──▶ ルーム（ロビー）
  └─「参加」────────▶ ルーム（ロビー）
                         │ ホストが開始
                         ▼
                 準備フェーズ → 予想フェーズ ⇄ 答え合わせ → 最終結果 → ロビーへ戻る
```

### 3.1 ホーム

- 名前入力（最大16文字。入力するたびに端末に保存）
- お題の概要（ストック件数 ／ 次のゲームに持っていく件数）と「お題の設定」ボタン
- 「部屋を作る（ホスト）」ボタン
- 部屋コード入力（6文字）＋「参加」ボタン。Enterでも参加。URLに `?room=コード` があれば自動で入力済みにする
- 部屋コードが入力済みのとき（招待リンクから来た／切断から戻った）は「参加」を主役のボタンにし、「部屋を作る」は控えめに表示する。それ以外は「部屋を作る」が主役（v0.5）
- 右上にバージョン（例：v0.7.1）を表示する。キャッシュなどで古い版を開いていないか確かめられるように（v0.7）
- 「あそびかた」（折りたたみ）
- 接続エラーなどのお知らせ表示欄

部屋を作る／参加するときの条件：
- 名前が空でないこと
- 「持っていく」にチェックしたお題が1つ以上あること

### 3.2 お題の設定

- お題ストックの一覧。各お題に「持っていく」チェック・編集・削除（確認あり）
- 「＋ お題を作る」ボタン
- 「← 戻る」でホームへ
- 初回起動時はサンプルのお題を10個入れておく（全員がサンプルのままでも10人まで遊べるように。同じお題は1つにまとめて配るため）（v0.5）

### 3.3 お題の作成・編集

- お題（最大60文字）
- 選択肢（各最大40文字）。最初は5個の入力欄。「＋ 選択肢を追加」で最大50個まで（v0.6 で上限10個を撤廃。50個は通信量と画面の都合による上限）。5個より多いときだけ ✕ で削除できる
- **出題数**（v0.6）：ゲームでこのお題が出たとき、選択肢の中から何個をランダムに出すか。5〜10個（ただし選択肢の数まで）。新しく作るお題は5個から始まる。v0.5 以前に作ったお題とサンプルは、選択肢の数（最大10）をそのまま出題数にする
  - 理由：選択肢を多めに作っておけば、同じお題でも毎回違う組み合わせで遊べる。出題数の上限を10にするのは、スマホで並べやすく、制限時間内に並べ切れる数にするため
- 選択肢の欄で Enter を押すと次の欄へ移る。最後の欄で Enter を押すと、10個未満なら欄を1つ足して移る（v0.5）
- 「保存」で端末に保存し、お題の設定へ戻る。「キャンセル」で破棄して戻る
- 保存時のチェック：お題が空でない／空でない選択肢が5個以上／選択肢が重複していない／出題数が5以上かつ選択肢の数以下
- 空欄の選択肢は保存時に取り除く
- 新規作成したお題は「持っていく」がオンの状態で追加される

### 3.4 ルーム（共通）

- 上部に「退出」ボタン（確認あり。ホストが退出すると部屋は解散）
- 確認（退出・お題の削除）は、ブラウザ標準のダイアログではなくアプリ内の確認画面で出す。アプリ内ブラウザ（LINE など）では標準のダイアログが出ず、押しても何も起きないことがあるため（v0.7）
- ロビー以外では参加者一覧（名前・得点・提出状況 ✅/⏳・ホストに👑・自分は枠付き・切断中は半透明）

## 4. ゲームの流れ

### 4.1 ロビー

- 部屋コード（6文字。紛らわしい文字 I, O, 0, 1 は使わない）を大きく表示
- http(s) で開いているときは招待リンク（`?room=コード`）とコピーボタン
- 共有機能がある端末（主にスマホ）では「共有」ボタンも出し、LINE などに直接送れるようにする（v0.5）
- 参加者一覧（人数／10、各人の持ち込みお題数）。ホストは他の参加者を ✕ で退出させられる
- **出題方式**（v0.7）：ホストはロビーで、お題の選び方を2つから切り替えられる（ゲーム開始まで何度でも）。参加者には今の方式が表示される。ロビーに戻っても前回の方式を引き継ぐ
  | 方式 | 選び方 |
  |---|---|
  | 全部からランダム（初期値） | 全員のお題をまとめた中から、自作のお題を優先してランダムに人数分選ぶ。誰のお題が何個出るかは運次第 |
  | 作成者ごとに1つずつ | 自作のお題を持ってきた人からは、まず1つずつ必ず選ぶ（作った人全員に見せ場を作る。柱3）。足りない分は残りの自作のお題、それでも足りなければサンプルから選ぶ |
- **制限時間**（v0.12）：ホストはロビーで、並び替えの制限時間を **30秒／60秒（初期値）／90秒** から選べる（ゲーム開始まで何度でも）。参加者には今の設定が表示される。ロビーに戻っても前回の設定を引き継ぐ。余裕を持って遊ぶか、あえて焦らせるかをホストが決められるようにするため。自由入力にしないのは、迷わず選べてテンポが落ちないため。「無制限」は作らない（遅い人が1人いると全員が待たされるため）
- 参加者のバージョンがホストと違うときは、ロビーに「違う版の人がいます（名前と版）。再読み込みしてもらってください」と出す。v0.7 以前の版は「不明」と表示される（v0.7）
- ホストのみ「ゲーム開始」。開始できない理由があれば表示：
  - 人数不足（オンラインの人数が最少人数未満）
  - お題不足（持ち込みお題の合計が人数未満）

### 4.2 準備フェーズ（自分の順位を決める）

1. 全員の持ち込みお題を1つにまとめ、ランダムに1人1つずつ配る
   - お題名と選択肢（順不同）がまったく同じお題は1つにまとめる（全員がサンプルのまま来ても、同じお題が複数人に配られないように）。作成者は先に部屋に入った人とする。手を加えていないサンプルは、作成者を「サンプル」と表示する（v0.5）
   - 自作のお題を優先して配り、足りない分をサンプルで補う（柱3）（v0.5）。選び方はロビーで決めた出題方式に従う（4.1、v0.7）
   - 配ったお題ごとに、ホストが選択肢の中から出題数だけをランダムに選び、並びもシャッフルする。当てられる人と予想する人には同じ選択肢が出る（v0.6）
   - 開始条件の「お題の数」も、まとめた後の数で数える
   - 自分が作ったお題がなるべく自分に当たらないようにする（300回まで試し、自作が当たる人数が最も少ない配り方を選ぶ）
   - 同じお題が2人に配られることはない
2. 各自、配られたお題を**自分の好み**で1位から順に並べて「決定」。画面にはお題の作成者を表示する（柱3）
3. 全員（オンラインの人）が提出したら自動で予想フェーズへ
   - 待っている間は「〇〇さん、△△さんを待っています」と、未提出の人の名前を出す（通話で「はやく〜」と言えるように）（v0.5。予想フェーズも同じ）
4. ホストは「未提出の人を待たずに進める」で先に進められる。並べていない人の分は、ランダムで埋める（時間切れと同じ扱い）
5. **問題数（ラウンド数）は、必ず参加人数と同じにする**（v0.8）。配られたお題は全部出題されるので、出題方式が「作成者ごとに1つずつ」なら、自作のお題を持ってきた人のお題は必ず出る

### 4.3 予想フェーズ（ラウンド）

- 順位を提出した人をランダムな順番に並べ、1人ずつ「当てられる側（ターゲット）」にする。ラウンド数 = 参加人数（v0.8）
- 表示：「ラウンド r / 全体」「〇〇さんの『お題』の順位は？」、お題の作成者（柱3。ターゲット・予想者のどちらの画面にも出す）
- ターゲット以外は順位を予想して「決定」。ターゲット本人は自分の回答を見ながら待つ
- ターゲット以外のオンラインの全員が提出したら自動で答え合わせへ
- ホストは「未提出の人を待たずに進める」で先に進められる

### 4.4 答え合わせ

正解を**最下位から1位へ、1つずつ自動でめくる**。外れた瞬間・当たった瞬間を全員が同時に見て、声でツッコめるようにする（柱1・2）。

#### 4.4.1 めくり（決定：2026-11-03）

| 項目 | 仕様 | 理由 |
|---|---|---|
| 順番 | 最下位 → 1位（カウントダウン式） | 一番盛り上がる1位を最後に持ってくるため |
| 進め方 | 自動。一定間隔で次をめくる | 誰も操作しなくても進むため |
| 間隔 | 1つにつき3秒。1位の前だけ「1位は…」と表示して2秒溜める ※暫定値 | 1位で引っ張るため。テストプレイで調整する |
| 同期 | ホストがめくるタイミングを決め、全員の画面を同時に更新する | 全員が同じ瞬間に見て声を出せるようにするため |
| 早送り | 「残りを一気にめくる」ボタン。押せるのはホストとターゲット本人 ※押せる人は暫定 | 選択肢が多いときや盛り上がりが薄いときに長引かせないため |

#### 4.4.2 画面

- 冒頭：「〇〇さんの『お題』」とお題の作成者を表示（柱3）
- 順位表：最下位〜1位の枠を最初から並べ、まだめくっていない枠は伏せておく。めくった枠に正解を表示する
- めくった直後の順位を大きく見せ、**その順位に全員が何を置いていたか**を並べる。正解した人に ✓、外した人に ✗
- 自分の行は「あなた」と表示して枠で目立たせる（自分が当たったか一目で分かるように。柱2）（v0.5）

```
【第3位】 たまねぎ

✓ たろう   たまねぎ
✓ はなこ   たまねぎ
✗ じろう   トマト
✗ さくら   じゃがいも
```

#### 4.4.3 全部めくり終わったあと

- 各予想者の予想を、1位から順に「合っている（緑）／違う（赤）」で表示。一致数・パーフェクト表示・獲得点も出す。獲得点の高い順に並べる
- 得点はこの時点で加算する（めくっている途中のランキングは動かさない）
- 最終ラウンド以外は「現在のランキング」も表示
- ホストのみ「次のラウンドへ」／最終ラウンドでは「結果発表へ」

### 4.4.4 制限時間（v0.6、v0.12 で選べるように）

| 項目 | 仕様 | 理由 |
|---|---|---|
| 対象 | 準備フェーズ（自分の順位）と予想フェーズの並び替え | テストプレイで「待ち時間」の不満が出たため（Q3） |
| 長さ | ホストがロビーで 30／60／90秒から選ぶ（初期値60秒。4.1） | v0.8 までは固定（30秒→60秒）。遊ぶ人によって合う長さが違うため、v0.12 で選べるようにした |
| 表示 | 残り秒数を画面上部に出す | — |
| 残りわずかの演出（v0.12） | **残り5秒**から（90秒のときは**残り10秒**から）：時間表示を赤くして脈打たせる／画面のふちを赤く点滅させる／1秒ごとに「カチ」と鳴らす／BGM のテンポを少し上げる（1.25倍）。提出済みの人には出さない。画面の動きを減らす設定の人は、点滅させず色だけ変える | 焦りを演出して声が出るようにするため（柱1）。90秒は長いぶん、早めに知らせる |
| 時間切れ | 並べ終えていれば、「決定」を押していなくてもその並びで提出する。並べ終えていないとき：**準備フェーズ**は、並べたところまでを生かして残りをランダムで埋める（問題数を参加人数とそろえるため。v0.8）。**予想フェーズ**は未提出扱いで、その人の予想は0点 | 決定：2026-11-04、準備フェーズの扱いを v0.8 で変更 |
| 答え合わせでの表示 | 時間切れの人を「時間切れ：〇〇さん」と出す | ツッコミのきっかけにするため（柱1） |
| 判定 | ホストが時間を管理する。通信の遅れを見込んで、ホストは締め切りの1.5秒後に締める | 端末ごとの時計のずれに影響されないため |
| 全員そろったら | 時間を待たずに次へ進む（今と同じ） | — |

ホストの「未提出の人を待たずに進める」ボタンは残す。

### 4.5 最終結果

- 得点順のランキング（同点は同順位。1〜3位はメダル表示）
- ホストのみ「ロビーに戻る」。オンラインの参加者は残り、得点は0に戻る。持ち込みお題はそのまま

## 6. 並び替えの操作

- 未配置の選択肢と「決定」ボタンは、画面の下に固定して常に見えるようにする。選択肢が多くてスクロールしても、押すものが画面の外に出ない（v0.5）
- 未配置の選択肢をタップすると、空いている一番上の順位に入る
- 配置済みの項目をタップすると未配置に戻り、その順位は空きになる（v0.6 で変更。ドラッグで好きな順位に置けるよう、空きを残す）
- 配置済みの項目は ▲▼ で1つ上下と入れ替えられる
- **ドラッグ＆ドロップ**（v0.6）：タップ操作に加えて、ドラッグでも並べられる
  - 配置済みの項目をつかんで上下に動かすと、並びが入れ替わる
  - 画面下の選択肢をつかんで順位の枠に落とすと、その順位に入る。上に空きがあっても、落とした順位に入る。埋まっている枠に落とすと、下（下に空きがなければ上）の空きまで1つずつずれる。何もない所で離すと元に戻る
  - マウスは少し動かすとつかめる。指は**少し長押し**してから動かす（すぐ動かした指は、画面のスクロールになる）。項目のどこをつかんでもよい（v0.9 で変更。⠿ は目印として残す）
  - スマホの指でもPCのマウスでも動く。つかんでいる間は項目が浮き上がり、落とす場所に目印を出す
  - ドラッグ中は画面のスクロールを止める。少し動かしただけ（数ピクセル）ではタップとして扱う
- 全部並べると「この順位で決定」が押せる。決定後は変更できない
- 順位は数字（1位〜N位）で表示する。S/A/B… のティア文字にはしない（決定：2026-11-04。並べるのは順位なので数字の方が迷わない。ティアらしさは色帯で出す）
- 順位の番号は色分け（1位＝赤 → 最下位＝青）
- 理由：スマホでもドラッグなしで操作できるようにするため

## 7. 通信・切断・データ保存

### 7.1 接続

- ホスト：`tierlistwars-v1-` ＋ 部屋コードを PeerJS のIDとして登録。IDが使われていたら別のコードで作り直す
- 参加者：その ID に接続し、名前と持ち込みお題を送る。15秒以内に応答がなければ失敗として扱う
- 参加者の識別：ブラウザのタブごとにIDと秘密の鍵を作る（タブを閉じるまで同じ）。IDは他の参加者にも見えるが、鍵はホストにだけ送る。同じタブで入り直せば同じ人として復帰できる
- 既に部屋にいる人のIDで接続してきた場合、鍵が一致するときだけ入れ替える。一致しなければ断り、本人の接続はそのまま残す（なりすまし・追い出し防止）

### 7.2 参加を断るケース

- ゲーム進行中の新規参加（同じ人の再接続は可）
- 満員（10人）
- 持ち込みお題が0件

### 7.3 切断

| 誰が | いつ | どうなる |
|---|---|---|
| 参加者 | ロビー | 参加者一覧から消える |
| 参加者 | ゲーム中 | 「切断中」になる。待ち対象から外れ、その人の分を待たずに進む。参加者側はホームに戻り、部屋コードが入力済みになるので「参加」を押せば復帰できる（同じタブに限る） |
| ホスト | いつでも | 部屋が解散。参加者には「ホストとの接続が切れました」と表示しホームへ |

### 7.3.1 接続の見張りと自動再接続（v0.6）

テストプレイ第1回で、予想フェーズに「並べ終わっても決定が押せず進まない」が起きた。コードを読んで切り分けた結果、**参加者側が切断に気づけず、送った予想がホストに届いていない**のが原因と見ている（スマホで通話アプリなどに切り替えると、ブラウザが裏に回って通信が切れることがある。これまでは送信に失敗しても何も表示していなかった）。

| 対策 | 内容 |
|---|---|
| 見張り | ホストと参加者は3秒ごとに合図を送り合う。10秒間何も届かなければ切れたとみなす |
| ホスト側 | 切れた参加者は「切断中」にして、その人を待たずに進められるようにする |
| 参加者側 | ホームに戻さず「再接続中…」と表示して、自動で入り直す（同じ人として復帰）。15秒たってもつながらなければホームに戻し、部屋コードを入力済みにする |
| 画面に戻ったとき | スマホでブラウザに戻ってきたら、すぐ接続を確かめる |
| 送信の確認 | 「決定」を押したら「送信中…」と出し、ホストから受け取りの返事（状態の更新）が来たら消す。3秒たっても返事がなければ送り直し、それでもだめなら再接続する |
| エラーの表示 | 予期しないエラーが起きたら、画面にエラー内容を出す（テストプレイで報告してもらえるように） |

### 7.4 端末に保存するもの

| データ | 保存先 |
|---|---|
| 名前、お題ストック | ブラウザの localStorage（同じ端末・同じブラウザでのみ残る） |
| 参加者ID | ブラウザの sessionStorage（タブごと） |

### 7.5 不正対策・セキュリティ

公開URLは誰でも開けるため、知らない人が混ざる・細工したデータが送られてくることを前提にする（2026-11-04 点検）。

| 対策 | 内容 |
|---|---|
| 受け取った内容の検査 | ホストは文字数の上限、選択肢の数、順位の形式、送れるフェーズかどうかを検査する |
| 表示前の無害化 | 名前・お題など人が入力した文字は、すべて無害化してから画面に出す。参加者IDは英数字以外を取り除く。参加者側も、ホストから届いた数値は数値に揃えてから使う |
| 正解の秘匿 | 正解（他人の順位）は答え合わせまで他の参加者に送らない |
| 部屋コード | 6文字（約10億通り）。当てずっぽうで他人の部屋に入れないようにする。紛れ込まれたらホストが ✕ で追い出す |
| 外部スクリプト | PeerJS は読み込み時に中身をハッシュ（SRI）で照合し、改ざんされていたら読み込まない |
| 検索避け | `noindex, nofollow` を指定し、検索結果に出にくくする |
| コミット名義 | 公開リポジトリのため、作成者は GitHub ユーザー名・非公開用メールアドレスにする |

仕組み上そうなるもの（対策しない）：
- 参加者同士の IP アドレスは互いに見える（P2P のため）
- 接続の仲介・中継に PeerJS の無料公開サーバーを使う。通信は暗号化されるが、稼働の保証はない
- 友人同士で遊ぶ前提のため、ホスト自身のズル（正解を覗く等）は対策しない
- 答え合わせが始まった時点で、正解と全員の予想はまとめて送られる（開発者ツールを使えば先に見られる）。予想は確定済みなので、得点には影響しない
- 細工した大量のデータを送りつけてホストを重くする攻撃は対策しない（部屋コードを知っている人しかできないため）
- 突然の切断（スマホのスリープ・回線断）は、ブラウザによっては検知が遅れる、または検知できない。その場合はホストの「未提出の人を待たずに進める」で先に進める

- 各自の曲は端末ごとの保存なので、ブラウザのサイトデータを消すと消える

## 10. モード：セレクトファイブ（v0.13。決定：2026-11-11）

壁打ちで決めた内容（2026-11-11）。今のモード（ティアリスト）の決まりのうち、ここに書いていないもの（参加人数、切断、制限時間の選び方など）はそのまま使う。

### 10.1 概要

- お題に対して、作者が登録した**正解とダミーを混ぜた選択肢**が並ぶ。答える人は、正解だと思うものを**ちょうど5つ**選ぶ
- **盛り上がる瞬間**：ダミーに引っかかる場面（「え、それダミーなの！？」「絶対正解だと思った…」）。主役はダミーを仕込んだ作者。答え合わせの締めくくりを、ダミーを明かす瞬間にする
- ダミーの出来に作者のセンスが出る（柱3）。全部当てたときの達成感（柱2）は、得点で味付けする

### 10.2 モードの選び方

- ホストがロビーで、モード（ティアリスト／セレクトファイブ）を選ぶ。出題方式・制限時間と同じ場所に置く。ゲーム開始まで何度でも変えられ、ロビーに戻っても前回の設定を引き継ぐ
- 1ゲームの中で遊ぶモードは1つだけ。ラウンドごとに混ぜない（ルール説明と画面の切り替えが増えて分かりにくいため）
- 遊んだ人の反応を見て、選び方を見直す（Q14）

### 10.3 お題の作成・編集

- お題のストックは、モードごとに分ける。「お題の設定」画面に、ティアリスト用とセレクトファイブ用のタブを設ける（中身の形が違うため）
- 1つのお題に登録するもの：

| 項目 | 範囲 | 理由 |
|---|---|---|
| お題 | 最大60文字 | 今のモードと同じ |
| 正解 | 5個以上（各最大40文字） | 5つ選ぶので、最低5個必要。正解とダミーは合わせて7個以上 |
| ダミー | 1個以上（各最大40文字） | ダミーがないと全部正解になってしまう |
| 出題する選択肢の数 | 7〜12個（初期値10） | 7より少ないと簡単すぎる。12より多いとスマホの画面に収まらない |
| うちダミーの数 | 1〜（選択肢の数−5）個（ただし登録したダミーの数まで）、または「おまかせ」（初期値は選択肢の数の半分） | 正解が5つを下回らないようにする。下限を1にしたのは、ダミーを1個だけ登録したお題も出せるようにするため（実装時に2から変更）。「おまかせ」は毎回ランダムに決めるので、答える人はダミーがいくつか分からない |

- 正解とダミーの合計は、最大50個（今のモードの選択肢の上限と同じ）
- 出題のたびに、登録した正解とダミーの中から、決めた数だけランダムに抜き出す。多めに登録しておくと、同じお題でも毎回違う組み合わせで遊べる
- 保存時のチェック：お題が空でない／正解が5個以上・ダミーが1個以上／正解とダミーを通して重複がない／決めた数を出せるだけの正解とダミーがある
- 同梱のサンプルのお題を10個用意する（ダミーの数はおまかせ）。サンプルは端末のストックには入れず、ホストが足りない分を補うときに使う
- 答える人には、ダミーの数を見せない（Q15。当面この形で遊び、反応を見て決める）

### 10.4 お題の配り方

- 今のモードと同じく、1人につき1つお題を配り、ラウンド数＝人数にする
- 自作のお題を優先する。出題方式（全部からランダム／作成者ごとに1つずつ）もそのまま使う
- 自作のお題が足りないときは、たくさん持ってきた人のお題から多めに出す。それでも足りなければ、同梱のサンプルで埋める（お題を作っていない人も、すぐに遊べるようにするため）

### 10.5 1ラウンドの流れ

1. **答える**：そのラウンドのお題の作者以外の全員が、同時に答える。制限時間はホストがロビーで選んだ長さ（4.4.4）
2. **答え合わせ**（10.7）
3. ホストの「次のラウンドへ」で次のお題へ。最後のラウンドのあとは最終結果へ（今のモードと同じ）

準備フェーズ（自分の順位を決める）はない。

### 10.6 画面

**答える人**
- 選択肢をカードで並べ、タップで選ぶ・外す。ドラッグは使わない（スマホで素早く操作でき、焦っていても押し間違えにくいため）
- 選んだ数を「3/5」のように出す。ちょうど5つ選ぶと、決定ボタンを押せる
- 時間切れのときは、選んだ分だけで提出したことにする（0個なら未提出扱い）

**作者**
- 正解とダミーの印を付けた選択肢を見せる
- 誰が提出したかだけ表示し、誰が何を選んでいるかは答え合わせまで見せない（通話で口を滑らせて、答えがばれないようにするため）

### 10.7 答え合わせ

| 順番 | 中身 |
|---|---|
| ① 正解 | 正解を1つずつめくり、それを選んでいた人の名前を並べる（「当てた！」の積み重ね） |
| ② ダミー | **最後の正解をめくるのと同時に**、ダミーをまとめて明かす。引っかかった人の名前を「〇〇 に引っかかった！」と出す。誰も選ばなかったら「誰も引っかからなかった…」と出す（作者がいじられる場面） |
| ③ まとめ | 一人ずつ、当てた数・獲得点を出す（今のモードの 4.4.3 と同じ形） |

- 自動で進め、「残りを一気にめくる」ボタンを付ける（今のモードと同じく、押せるのはホストと作者）
- めくる間隔は今のモードと同じにして、テストプレイで調整する
- 当初は、正解のあとに「この中にダミーが○個…」と溜めてから、ダミーを1つずつめくる形だった。試したところ、演出がくどく、テンポが悪く感じたので、最後の正解と同時に明かす形に変えた（2026-11-11）

### 10.8 得点

| 項目 | 点 |
|---|---|
| 正解を1つ選ぶごと | +1 |
| 5つ全部正解（パーフェクト） | さらに +3 |
| ダミーを選ぶ | 減点なし |
| 作者 | 得点なし |

- 減点しないのは、勝ち負けを重くしないため（1.3）。ダミーを選んだときの痛みは、点ではなく答え合わせの演出で出す
- 未決：誰かがダミーを選ぶたびに、作者にも点を入れるか（Q16）

## 11. モード：運命の二者択一（v0.14。決定：2026-11-11）

壁打ちで決めた内容（2026-11-11）。**［提案］** と付けたところは、壁打ちで話していない細部を Claude が補ったもので、そのまま合意した。

### 11.1 概要

- 2択のクイズ。参加者は自分のキャラクターを画面の左右どちらかへ動かして答える。不正解の人は脱落し、最後の1人になるまで続ける
- **盛り上がる瞬間**：脱落の瞬間（「うわー、落ちた！」「道連れだ…」）。正解の発表と同時に、不正解の側の床が抜けて、そこにいた全員が一斉に落ちる。移動の駆け引き（「みんなそっち行くの！？」）は味付け
- ゲームというより演出が主役。事実のクイズとして作る（別のモードなので、人の好みを読む柱には縛られない）

### 11.2 モードの選び方と制限時間

- ホストがロビーで「モード」を「運命の二者択一」にする（10.2 と同じ）
- 1問の制限時間は、このモード専用にする。ホストがロビーで **5秒／10秒（初期値）／15秒** から選ぶ。今のモードの 30〜90秒は2択には長すぎるため
- 残りわずかの演出（4.4.4）は、残り3秒から出す ［提案］

### 11.3 問題の作成・編集

- 「お題の設定」に「運命の二者択一」のタブを足す（10.3 と同じく、モードごとにストックを分ける）
- 1問に登録するもの：問題文（最大60文字）・正解（最大40文字）・不正解（最大40文字）
- 同梱のサンプルを30問ほど用意する。端末のストックには入れず、足りない分をホストが補う（10.3 と同じ扱い）

### 11.4 問題の束

- ゲームが始まったら、全員が持ってきた問題（同じ問題は1つにまとめる）を先に、そのあとに同梱のサンプルを並べて、1ゲーム分の問題の束を作る。順番はそれぞれの中でランダム ［提案］
- 正解を左右どちらに出すかは、1問ごとにランダム
- **作った人は、自分の問題では自動でセーフ**（答えを知っているので、正解しても不公平になるため）。動くことはできるが、結果には関わらない ［動けるかどうかは提案］

### 11.5 1問の流れ

1. **出題**：問題文と、左右の答えを出す。全員のキャラクターは真ん中に立った状態から始まる ［提案］
2. **移動**：締め切りまで、何度でも左右に動ける。全員の位置がリアルタイムで全員に見える
3. **締め切り**：その瞬間にいた側を答えとする。**真ん中のままの人は不正解**として扱う ［提案。動かない人が得をしないように］
4. **発表**：正解の側を光らせ、同時に不正解の側の床が開いて、そこにいたキャラクターが一斉に落ちる。落ちた人の名前を出す
5. 数秒おいて、自動で次の問題へ進む ［提案。テンポを優先し、ホストのボタンを待たない。ホストには「一時停止」を付ける］

### 11.6 終わり方と、全員が同じ結果のとき

| 場面 | 扱い |
|---|---|
| 生き残りが1人になった | その人の勝ちで終わる |
| 全員が不正解 | 全員セーフにして、次の問題へ（「全員落ちたけど、今回は救済！」と出す） |
| 全員が正解 | そのまま次の問題へ |
| 問題がなくなっても、2人以上残っている | 残った全員の勝ち |

### 11.7 脱落した人（ゴースト）

- 脱落した人は**ゴースト**になり、次の問題からも左右に動き回れる
- 生き残っている人の画面にも、ゴーストは半透明で見える。正解の側に誘い込んだり、逆の側に集まって惑わせたりできる（「だまされるな！」）
- ゴーストは結果に関わらない。生き残っている人とはっきり見分けが付くようにする（半透明・ゴーストのポーズ）
- 答えそのもの（問題文や答えの文字）を見えなくする邪魔はしない。クイズとして不公平になって冷めるため
- 「もう少し邪魔ができてもよい」という声があり、強化はあとで考える（Q17）

### 11.8 キャラクター

| 項目 | 仕様 |
|---|---|
| 用意の仕方 | 画像生成で作った絵を、プリセットとして同梱する |
| 数 | 17体：動物12＋アニメ風の人5（ゆうしゃ・まほうつかい・にんじゃ・アイドル・かいぞく。v0.15 で追加。どれもオリジナルで、実在の作品のキャラクターは使わない） |
| 選ぶ場所 | ホーム画面（名前の下）。このモードのロビーでも変えられる。端末に保存する |
| 同じキャラ | 重複してよい。名前と枠の色で見分ける |
| ポーズ | 「立ち」「移動中」「落ちる（驚き顔）」「ゴースト」の4つ |
| 絵の雰囲気 | 今の画面（水色のポップな色、太い黒の縁取り）に合わせた、丸っこい動物など |
| 進め方 | まず2体を試しに作って見てもらい、雰囲気が決まってから残りを作る |

**v0.14 の時点では、絵はまだ仮のもの**（動物の絵文字12種を丸い枠に入れたもの。ポーズは傾き・汗・おばけの印で表す）。画像生成の費用をかけない方針のあいだは、この仮の絵で遊ぶ。絵を作ったら `src/modes/fate/charas.tsx` の中身を差し替える（ほかの画面は変えなくてよい）。

### 11.9 順位

- 勝ち残った順で順位を付ける。最後の1人が1位、そのあとは落ちるのが遅かった順。同じ問題で落ちた人は同じ順位
- 得点は使わない（このモードでは「最後まで残った」ことが一番の見せ場のため）
- 最終結果の画面では、順位と、それぞれが何問目で落ちたかを出す ［提案］

### 11.10 通信

- 位置が変わるたびにホストへ送り、ホストが全員に配る。10人までなら通信量は問題にならない
- 締め切りの判定はホストの時計で行う（4.4.4 と同じ）。通信の遅れで締め切りの直前に動いた分が届かないことがあるため、ホストは締め切りの少しあとに締める ［提案］

### 11.11 実装で決めた細部（v0.14）

仕様に書いていなかったところを、実装のときに次のように決めた。

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 締め切りの猶予 | 0.5秒（今のモードは1.5秒） | 制限時間が5秒のこともあるので、猶予が長いと締め切り後に動けてしまう。参加者の画面では、0秒になった時点で動けなくする |
| 発表を見せる時間 | 5秒 ※暫定値 | 床が開く → 落ちる → 名前を読む、に足りる長さ。テストプレイで調整する |
| 同じ問題を複数の人が持ってきた | 持ってきた全員を「作った人」として、自動でセーフにする | 全員が答えを知っているため |
| 「全員が不正解」の数え方 | 作った人とゴーストを除いた、生き残りの全員が不正解のとき | 作った人以外が全員落ちると、自分の問題で勝ち残れてしまうため |
| 切断中の人 | 真ん中に立ったまま扱いになり、次の締め切りで落ちる（全員不正解なら救済される） | 特別な決まりを増やさないため |
| 一時停止 | ホストが、出題中でも発表中でも止められる。再開すると、残り時間から続く | 11.5 の「一時停止」を、出題中にも使えるようにした |
| 画面 | 参加者の一覧と得点は出さない（舞台の上に全員がいるため）。生き残りの人数を出す | — |
| 音 | 出題・発表・結果で BGM を変えない（並び替えの曲のまま）。効果音「床が開いて落ちる」「助かった」を足した | 数秒ごとに曲が変わると落ち着かないため |
| 操作 | 左右の答え・床をタップ。キーボードの ← → でも動ける | — |

### 11.12 3D表示（v0.15。決定：2026-11-12）

舞台を3Dでも見られるようにする。2D表示（v0.14）はそのまま残す。

| 項目 | 仕様 | 理由 |
|---|---|---|
| 切り替え | 舞台の下の「2D／3D」で、各自が自分の端末の表示を選ぶ（端末に保存。初期値は3D）。同じ部屋に2Dの人と3Dの人が混ざってよい | ルールと通信は同じで、描き方だけが違うため。古い端末で重い人は2Dにできる |
| 3Dにする範囲 | 舞台（左右の床・スタート台・キャラクター）だけ。問題文・答え・残り時間・結果画面は今のまま | 文字は今の画面の方が読みやすい |
| 視点 | 斜め上から見下ろす。動かせない | 全員の位置がひと目で分かるように |
| 床 | 厚みのある台。不正解の床は、2枚の扉が下に開く。正解の床は緑に光る。全員不正解のときは、開いてすぐ閉じる | 2Dと同じ決まりを立体で見せる |
| キャラクター | 球や円すいを組み合わせた、おもちゃ風の動物12種と、アニメ風の2頭身の人5種（2Dの絵文字と同じ並び）。足元の輪の色と名前の札で見分ける。**試作の段階**で、まず「いぬ」「ねこ」を見て雰囲気を決める | 費用をかけずに作れる形。2Dのコード描画は評価が低かったので、試作で確かめてから進める |
| ポーズ | 立ち（ゆっくり弾む）／移動中（跳ねながら向かう）／落ちる（目を見開いて空中でじたばた → 回りながら穴へ）／ゴースト（半透明で白っぽく、浮かぶ） | 11.8 の4ポーズ |
| 操作 | 2Dと同じ（上の答えをタップ、床をタップ、← →） | — |
| 動きを減らす設定 | 揺れ・じたばた・回転を出さず、落ちる人は小さくなって消える | 8.2 と同じ配慮 |
| 3Dが使えない端末 | 自動で2D表示にする | WebGL が動かない環境があるため |
| 読み込み | 3Dの部品（three.js）は、3D表示を選んだ人だけが読み込む | 2Dの人の読み込みを重くしないため |
